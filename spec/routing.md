# 经验路由规范 (Experience Routing)

> 状态:2026-09-30 第二版。第一版(09-29 草稿)之后做了三件事:读了 Claude Code 程序里的菜单开关、
> 调研了 Codex / opencode / pi / Gemini CLI / Cursor 的 skill 加载方式、拿一台机器的历史会话做了回放。
> 第 7 节列出哪些已经实现、哪些还没有。第 2、6 节的数字都来自一台机器、一个使用者,取样条件写在表里。

**一句话**:经验库越大,越不能指望模型从一张平铺的菜单里自己挑中该用的那条。
常驻菜单只放少数条目,并按项目、按文件让位;其余靠一个查找命令 `whetstone find` 按需查;
查找从历史会话里学「使用者怎么说 → 用了哪条」。默认不装任何钩子。
核心只读一种统一格式的会话事件,每种 agent 运行时各写一个适配器。

## 1. 这是什么,为什么要有

**路由 = 决定「这一刻哪条经验该进入模型视野」的机制。** 它不产生经验,也不判断经验对错
(那是蒸馏和 `use-time-conflicts.md` 的事),只管经验在该出现的时候出现。

**没有它会怎样**:运行时把每个 skill 的名字和描述拼成一张菜单放进上下文,模型读描述决定用哪个。
Claude Code 的菜单有总预算;超了不删 skill,而是去掉一部分描述、只留名字 —— 描述里写的触发词,
模型就看不到了。预算固定,库一直长,平分到每条描述的份额越来越小:

| 库里的 skill 数 | 每条描述能分到(Opus 会话,留给库约 16,000 字符,每条名字和格式约 20) |
|---|---|
| 65 | 约 226 字符 |
| 100 | 约 140 |
| 200 | 约 60 |
| 300 | 约 33 —— 低于一条能被匹配的描述需要的 40 |

上下文小的模型更早撑不住:同一个库在 Haiku 4.5 会话里只有约 7,978 字符的菜单,65 个 skill 全部只剩名字。
别的运行时情况不同(第 5.3 节):Codex 也有上限,超了先砍描述再整条删;opencode、pi、Gemini CLI 没有上限,
库越大常驻越贵,只会稀释。

**为什么不是继续缩描述**:缩描述只是推迟上面那张表的结局。入口不能跟着 skill 数一起变长 ——
只能是**固定大小的入口 + 按需查找**,或者**由确定的信号(在哪干活、碰了什么文件)直接带出来**。

## 2. 实测依据(Claude Code,一台机器)

| 事实 | 样本 | 结果 |
|---|---|---|
| 按工作目录触发(常驻规则写明「在某目录下用某 skill」) | 30 天、10 个会话 | 8 个加载了对应 skill |
| 按描述里的触发词触发 | 30 天、38 组「会话 × skill」 | 5 组加载(13%) |
| 同上,按菜单里有没有描述拆开 | 197 条命中消息 | 有描述 26%(98 条);只剩名字 1%(99 条) |
| 菜单预算 | 76 份会话开头的菜单(Opus) | 24,536–26,880 字符 |
| 预算跟模型走 | 同一个库,Opus 与 Haiku 4.5 各一份 | 25,123 字符 / 7,978 字符 |
| 超预算时砍谁 | 程序 2.1.284 原文 | 按 `usageCount * max(0.5^(距上次调用天数/7), 0.1)` 排,分低的只剩名字 |
| `skillOverrides` 设置项 | 程序 2.1.284 原文 | `on` / `name-only`(只列名字)/ `user-invocable-only`(模型看不到,`/名字` 还能用)/ `off`;按 local → project → user 读 |
| `skillOverrides` 在哪一层生效 | 4 个无交互测试会话 + 1 个对照(2026-09-30,Sonnet;Haiku 的菜单本来就全是名字,看不出差别) | 不在 git 仓:只有从设置文件所在目录启动的会话读到,从子目录启动读不到;在 git 仓里:从仓根或子目录启动都读到 |
| frontmatter `paths` | 2 个无交互测试会话(2026-09-30) | 开局菜单里没有;只读别的文件不出现;读到匹配的文件后菜单追加这一条 |
| `<目录>/.claude/skills/` | 4 个无交互测试会话 | 从该目录或子目录启动:有;从别的项目启动:没有;从上层启动、读到该目录的文件:同一秒补进 |

(`--allowedTools` 不用 `=` 会把后面的提示当成工具名吞掉)。菜单用 `whetstone menu-snapshot --events` 看。
统计脚本与完整报告在使用者的私有库,不随本仓发布。比率只描述这段时间,不能外推。

## 3. 原则

1. **确定信号优先于模型判断。** 目录、文件路径是事实;「模型读了描述觉得相关」是推断。上表里前者 8/10,后者 13%。
2. **只给指针,不塞正文。** 自动带出的东西只说「有这条经验、在哪」,读不读正文由模型决定。
3. **钩子最少**(user 2026-09-29 定)。默认一个都不装;要装先满足第 8 节。
   **为什么**:干活时执行命令、读写文件极其频繁,挂在上面的钩子几乎每一步都跑;它坏的方式是「一直在响」。
4. **不要求使用者记住 skill 的名字。** 不用「只许手动调用」来省菜单 —— 库大了使用者根本不知道有哪些 skill。
   例外:本来就只由人点名用的维护命令。
5. **从使用里学,不写死**(user 2026-09-29 原话:「实际每个目录根据使用情况的不同,用到的经验也会存在变化的,
   我们的路由要智能一点」)。学习只读事后的会话记录,不为此装钩子。
6. **给错比不给糟,所以要有门槛。** 查找够不上门槛就明说「没有合适的」。依据:SkillLens(arXiv 2605.23899)
   25% 的组合出现负迁移;SkillsBench 84 个任务里 16 个加了 skill 反而变差(作者自报)。
7. **改动靠回放决定,不靠感觉。** 每个改动在历史会话上按时间回放,逐例比赢的够多、输的够少才保留(第 6 节)。
8. **运行时中立**(user 2026-09-30:「别人可能使用其他 agent,例如 codex,opencode,pi」)。
   学习、查找、评测只读统一事件格式(第 5.1 节);运行时专属的只放 `adapters/`。

## 4. 结构:常驻、按需、学习三层

### 4.1 常驻层(菜单,只用运行时自带的开关)

| 做法 | 做什么 | 为什么 |
|---|---|---|
| 路由 skill(`whetstone route catalog <库>` 生成,默认名 `experience-router`) | 入口描述 ≤ 200 字符:「不确定有没有经验时先跑 `whetstone find` 或查这里」;正文是整个库的分族目录 | 固定大小的入口,库再大菜单里也只占一条 |
| 常驻规则里一句话(Claude Code 是 `CLAUDE.md`,其他是 `AGENTS.md`) | 同上一句 + 路径 | 路由 skill 是新的、没调用记录,超预算时它最先被砍成只剩名字;常驻规则不受菜单预算影响 |
| 按项目让位(Claude Code:`.claude/settings.local.json` 的 `skillOverrides`,写在 git 仓根;不在 git 仓就写在项目目录本身,这时只有从该目录启动的会话读得到) | 用得明显集中在别的项目、本项目没用过的,设 `name-only`(`whetstone route plan`) | 不是藏起来:名字还在,照样能调用,只是把描述预算让给本项目用得上的。**合并写入,不覆盖**:`/skills` 界面也写这个文件,使用者自己设过的条目不改 |
| 跟文件绑定的经验加 `paths` | 碰到匹配的文件才进菜单 | 不碰文件时不占预算(第 2 节实测)。代价:只聊话题、没碰文件时它不在菜单里,要靠 `find` 或路由 skill |
| 只在一个项目里成立的经验放项目目录(`skill-scopes.tsv`,`deploy.sh --link` 读) | 链进 `<目录>/.claude/skills/`,不进全局 | 产品工作流这类只在一个项目成立的;跨项目的专题经验不要这样放,会在别处看不见 |

### 4.2 按需层:`whetstone find "<要做的事>"`

- **打分**:BM25F(Robertson & Zaragoza 2009 的字段加权版),字段和权重:名字 3、描述 2、正文 1、学到的原话 2。
  **正文要搜**:SkillRouter(arXiv 2603.22455)去掉正文后首位命中 56.0% → 18.7%(作者自报)。
- **切词**:英文按词(去复数 s、去虚词);中文按相邻两个字,去掉常见虚词(这个 / 问题 / 帮我……)。
  中文没有空格,单字几乎什么都能配上,整段又几乎什么都配不上,两个字是常用的折中;本机 sqlite 也没有三字切词器。
- **门槛**:覆盖率 = 这条 skill 配上的查询词权重 / 查询词总权重;库里没有的词,每个按已知词的平均权重计入总权重
  (不计入时,「hello world weather」因为一条 skill 里碰巧有 hello 就成了 100%)。默认 0.3,
  **是起点值,还没有被数据定下来**(第 6 节)。
- **查哪些目录**:各运行时加载 skill 的目录 —— 从当前目录往上各层的 `.claude/skills`、`.agents/skills` 等,再到用户目录;
  同名时近的优先。只许手动调用的、路由 skill 本身不列。
- **输出**:最多 3 条,每条一行名字 + 覆盖率 + 配上的词 + 路径,一行描述;都不够门槛就说
  「no skill fits well enough …; go ahead without one」。`--json` 给程序用。

### 4.3 学习层(离线,读会话记录)

| 学什么 | 怎么学 | 状态 |
|---|---|---|
| 原话 → skill | `whetstone route learn`:每个会话里每个 skill 第一次被用之前,使用者打的最后一条消息,并进该 skill 的「学到的原话」字段(截到 400 字符)。使用者自己 `/名字` 点的不学 | 已实现,回放判「保留」 |
| 项目 → skill | `whetstone route usage`:同一 skill × 项目 × 会话只计一次,按半衰期 30 天折算 | 表已实现;拿它给查找加分,回放判「更差」,不用(第 6 节) |
| 文件 → skill | 加载前碰过的文件,提议成 `paths` | 未做 |
| 按项目让位的建议 | `whetstone route elsewhere` 判哪些属于别的项目(至少 3 个会话、其中至少 2/3 在另一个项目、本项目 0 次,门槛事先定好);`route plan` 翻译成 `skillOverrides`,默认只打印,`--write` 才合并写入 | 已实现。本机 60 天数据下三个项目都是 0 条(被用过 3 次以上的只有 2 个 skill,最集中的一个是 5/8 = 62.5%,不到 2/3) |

**「在哪个项目里干活」怎么定**:加载之前这个会话最后碰的文件,往上找第一个带项目标记的目录
(`.git`、`.repo`、`AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 或运行时的点目录),不进用户主目录本身
(主目录有 `~/.claude`,会把所有没标记的目录都吞掉);没碰文件就用启动目录。
**跳过**:运行时自己的目录(`~/.claude`、`~/.codex`、临时目录……)和 skill 自己的目录 ——
读会话记录、临时文件、skill 自己的参考文件,不是在项目里干活。
实测:不跳过时 43 次加载里 20 次记到了 `~/.claude/projects` 或 `/tmp`(两处都有 `.git`)。
**根目录本身就是 skill 的仓**(`SKILL.md` 和 `.git` 在同一层)算项目,不算 skill 目录。

**曝光修正**:描述看不见期间没被加载,不当作不需要。不从「没用过」推出让位、收窄或停用
([推断,依据第 2 节:有描述时触发率 26%,只剩名字 1%] 没被用上更可能是看不见)。

### 4.4 钩子

默认 0 个。要装先满足第 8 节。

## 5. 通用性:核心与适配器

**做法**:`bin/route.py`(学习、查找、评测)只读一种统一格式的会话事件;每种运行时一个适配器,负责三件事:
① 把它的会话记录转成统一事件;② 把「让位 / 按文件出现」翻译成它的开关;③ 写常驻的那一行指针。
**为什么这样分**:六家的会话格式、菜单开关各不相同(第 5.3 节),但「使用者说了什么、碰了哪些文件、用了哪条经验」
这几件事每家都有。学习和评测只依赖这几件事,就不用每家各写一遍。

### 5.1 统一会话事件格式(一行一个 JSON)

每行必带 `v`(格式版本,现为 1)、`runtime`、`session`、`ts`;`src`(`<会话文件>:<行号>`)可选,用来回查。

| kind | 字段 | 说明 |
|---|---|---|
| `session` | `cwd` | 每个会话第一行;没有它之前的记录不产出事件 |
| `user` | `text`, `cwd` | 使用者打的字;工具结果、系统注入、命令输出、压缩摘要都不算 |
| `file` | `path`(绝对路径), `op` | `read` / `edit` / `write` / `search` |
| `load` | `skill`, `via`, `use` | `via`:`tool`(专用工具)/ `user`(使用者点名)/ `read`(读 SKILL.md)/ `shell`(从命令里解析出来);`use`:算不算真的在用,**由适配器判断** |
| `menu` | `full`, `described`, `names_only` / `added` | 开局的完整菜单,或中途追加的名字;运行时不记录菜单时不产出 |
| `find` | `query` | 模型跑了 `whetstone find`,记下它写的查询 |

**`use` 为什么交给适配器**:各家「用一条经验」的方式不同。Claude Code 有专用的 Skill 工具,读 SKILL.md 多半是在改它
(`use: false`);Codex、pi、Cursor 没有专用工具,读 SKILL.md 就是在用(`use: true`)。

**`find` 为什么要记**:回放现在只能拿使用者的原话当查询(第 6 节),而实际查询是模型自己写的,短得多。
攒够模型写的查询后,门槛应改用它们来定。

## 6. 评测:按时间回放(`whetstone route replay`)

**规则**(照 autoresearch 的「只在变好时保留」,补上它没有的几样):

- **按时间切**:评某个会话,只用它之前开始的会话学出来的东西。
- **一个例子** = 某会话里某 skill 第一次被用,和那之前使用者打的最后一条消息。库里已经没有的 skill 不评。
- **逐例比**:新做法的排名比旧做法靠前算赢、靠后算输。**5 胜 0 负或 7 胜 1 负、胜例来自至少 2 个项目才保留**;
  输比赢多判「更差」;其余判「证据不足」—— 不算失败,数据少时这是如实的结果。
- **打分脚本先验自己**:随机排序必须低于只看文字;提前看到答案的排序(把这条消息也算进学到的原话)必须高于正常学习。
  两条有一条不成立,这次回放的数字不可信,退出码 1。
- **公式先定后测**:一个做法只测事先写下的那一个公式,不在同一批例子上反复调参。

**2026-09-30 第一次回放**(一台机器 83 个会话;44 个带消息的首次使用,其中 10 个的 skill 已不在库里;库 65 个 skill):

| 做法 | 前 1 | 前 3 | 逐例比 | 结论 |
|---|---|---|---|---|
| 随机(自检用) | 1 | 3 | —— | —— |
| 只看文字(名字 + 描述 + 正文) | 5 | 9 | —— | 基线 |
| + 学到的原话 | 6 | 12 | 对只看文字:9 胜 0 负,胜例来自 6 个项目 | **保留** |
| + 本项目用过就加分(`1 + n/(n+2)`) | 5 | 13 | 对学原话:3 胜 4 负 | **更差,不用** |
| 提前看到答案(自检用) | 28 | 30 | —— | —— |

**门槛还没定下来**:门槛 0.3 时,34 个例子里给对 4、给错 10、没给 20;
「之后没用任何 skill」的 3,322 条消息里,45% 也会给出结果。把门槛提到 0.45,给错降到 3,给对也只剩 2。
**原因**:这里拿使用者的原话当查询 —— 原话长、口语化,很多靠上下文(「开始 clone 仓库吧」)。实际查询由模型写,
关键词集中得多。所以:① 门槛暂用 0.3 这个起点值,输出里带覆盖率让模型自己判断;
② 适配器已开始记录 `find` 事件,攒够模型写的查询后重新定。

**另一个已知偏差**:回放用的是 skill **现在的**文字,而有的描述是在当时没被用上之后才补的触发词,
只看文字那一行因此偏高。

## 8. 钩子准入条件(全部满足才能提议装)

1. **离线回放的数字**:每个会话提示次数中位数 ≤ 1,90 分位 ≤ 3(暂定,user 可改);写明能补回哪几个漏掉的例子。
2. **提示只给模型看**,不在使用者屏幕上刷出来(2026-09-15 撤掉旧钩子,就是因为提示整段打到了屏幕上)。
3. **同一条经验每个会话最多提示一次,每轮最多一条。**
4. **不拦任何操作**,只提示。
5. **一个开关整个关掉**(环境变量),关掉后行为和没装时相同。
6. **装上一周后重测**:提示过的经验真被用上的比例太低,就撤。

旁证:开源的 skill-router(lomeshdutta)试过每条消息都跑的钩子,作者原话「评测分数好,真实会话里太吵」,v0.2 改成每会话一次。

## 9. 禁止清单

1. 不用 `disable-model-invocation` 来省菜单空间(原则 4 的例外除外)。
2. 不从「没用过」推出让位、收窄或停用(4.3 曝光修正)。收窄、让位一律 user 确认。
3. 不装没经过离线回放的钩子。
4. 钩子和路由都不往上下文里塞经验正文,只给指针。
5. 路由目录不手工改 —— 只由生成器写,改了会在下次生成时被覆盖。
6. 机器相关的东西(作用域清单、学到的原话、使用表)不进可移植的包。学到的原话是使用者自己打的字,
   只存本机(默认 `~/.local/share/whetstone/route-learned.jsonl`)。
7. 核心(`bin/route.py`)不读任何运行时专属的格式;新运行时只加适配器。
8. 回放判「证据不足」或「更差」的做法不进 `find` 的默认行为。

## 10. 边界

- `find` 和路由 skill 仍依赖模型想起去用。常驻规则那一句和 `paths` 减轻它,不能保证。
- 离线回放测不了「模型按话题主动去查」这一步,只测「查了之后排得准不准」。
- `skillOverrides`、`paths`、项目目录的行为只在 Claude Code 上测过;别的运行时的开关是读代码得出的,没有实测。
- 菜单预算随模型变。上下文小的模型上菜单几乎全是名字,`find` 和路由 skill 是唯一可靠的入口。
- 学到的只是「过去用过」;新方向刚开始时没有记录,只能靠文字。样本只来自一台机器、一个使用者。
- 不解决经验内容本身对不对 —— 那是 `use-time-conflicts.md`;库里没有的经验,是蒸馏的事。
